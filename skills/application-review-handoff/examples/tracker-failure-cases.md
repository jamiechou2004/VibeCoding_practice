# 独立离线验证

仅阅读指定技能与 tracker-config.md，依据虚构场景判定；未访问网络、申请或表格，未修改技能，未读取其他私人记录。“允许”不是实际执行。

| 场景 | 是否允许写入 | 实际判定与下一动作 |
|---|---|---|
| 1 最新指定新主表；Acme D1/D2 各一行 | 允许定点更新新表 D1 | 最新指定覆盖旧配置。核对 SYNTHETIC_NEW/gid42、招聘跟进/Applications 和实际列映射后，只更新唯一 Acme＋D1；不动 D2、不追加 D1、不写旧表、不自行增列。仅同目标同范围回读一致后标已同步。 |
| 2 实际返回 gid7 | 不允许 | 指定 gid42 与实际 gid7 不符，停止写入并报告差异；保留本地待同步项，重验正确目标。 |
| 3 标签 Archive，缺 Role ID | 不允许 | 报告 Applications→Archive 和缺列两项差异，先解决身份/映射冲突；不静默改配置或增列，不凭公司名称猜行。 |
| 4 Acme D1 两行 | 不允许 | 先消歧；不任意选行、合并或追加重复 D1。 |
| 5 新增 D3 超时，回读一致 | 已验证成功，无须重写 | 在原新增已满足授权、身份核验和零匹配前提下，超时后先回读；同 ID/gid/范围值一致即可标已同步，不重复追加。提交与归档状态另记。 |
| 6 返回成功，回读不符 | 不允许盲目重写 | 不标已同步，记录预期/实际差异并保留待核验或未同步状态；查明原因后再决定定点修正，不盲目覆盖或追加。 |
| 7 新表拒绝访问，旧表可访问 | 不允许回退写旧表 | 保留新目标访问阻碍及本地待同步项；可归档已确认材料，但不能标闭环完成。恢复新表访问后再核验。 |
| 8 无官方 JD，仅授权准备 | 不允许提交；无依据写主表 | 官方要求保持待核验，匹配为信息不足；仅准备材料/审核包和本地记录，不将第三方摘要当已确认要求，不扩展提交或主表维护授权。 |
